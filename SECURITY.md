# Security Policy

## Supported versions

Security fixes are applied to the default branch (`main`) of this repository. Published docs at docs.elosync.com should track `main`.

## Reporting a vulnerability

**Please do not open a public GitHub issue for security vulnerabilities.**

Report privately using one of:

1. **GitHub Private Vulnerability Reporting** — [EloSync-Docs Security Advisories](https://github.com/DiligentCreators/EloSync-Docs/security/advisories/new)
2. **Email** — [security@elosync.com](mailto:security@elosync.com)

Include as much detail as you can: affected page/path, reproduction steps, impact, and any proof-of-concept (non-destructive preferred).

## What to expect

- We aim to acknowledge reports within **3 business days**.
- We will keep you informed of triage status and remediation when a fix is planned.
- Please give us a reasonable window to patch before any public disclosure.

## Scope

In scope: XSS or injection in the docs site itself, accidental publication of secrets/credentials, and similarly severe issues in EloSync documentation tooling or content that exposes sensitive data.

Out of scope: general product vulnerabilities that belong in the Backend, Frontend, Website, or Mobile repos (please report those against the affected repository), denial of service only, and social engineering.

## Safe harbor

We will not pursue legal action against researchers who report in good faith, avoid privacy violations and service disruption, and follow this policy.
